# 团队审查清单

## 概述
统一代码审查标准，确保 AI 审查 Agent 按照团队标准执行四维审查。

## 触发条件
- Reviewer Agent 启动时
- /review-code 命令触发时
- MR 提交后

## 审查维度

### 1. 规范检查

- [ ] 命名是否符合团队命名规范
- [ ] 文件组织是否符合团队目录结构约定
- [ ] 代码格式是否一致（indent, 引号, 分号等）
- [ ] 是否有重复代码可抽取
- [ ] 导入顺序是否合理（标准库 → 第三方 → 内部模块）
- [ ] 是否有未使用的 import/变量

### 2. 安全审查

- [ ] 是否存在 SQL 注入 / XSS 风险
- [ ] 敏感数据是否硬编码（API key, password, token）
- [ ] 用户输入是否经过验证和清洗
- [ ] 文件路径操作是否有目录遍历风险
- [ ] API 端点是否有鉴权保护
- [ ] 日志是否包含敏感信息

### 3. 性能审查

- [ ] 是否存在 N+1 查询问题
- [ ] 是否存在不必要的同步阻塞调用
- [ ] 循环中是否有可优化的重复计算
- [ ] 前端组件是否有可能的重渲染问题
- [ ] 大数据量操作是否有分页/流式处理
- [ ] 是否有内存泄漏风险（未清理的定时器, 事件监听）

### 4. 架构一致性

- [ ] 实现是否符合架构设计文档
- [ ] 是否有 scope creep（超出需求范围的改动）
- [ ] 模块职责是否清晰，有无职责越界
- [ ] 是否遵循依赖倒置（高层模块不依赖低层模块）
- [ ] 新增依赖是否合理，有无已有方案可复用

## 审查输出格式

```markdown
## 代码审查报告

### 严重问题 (CRITICAL)
- [ ] 无 / 列出具体问题

### 建议改进 (MEDIUM)
- [ ] 列出具体问题

### 优化建议 (LOW)
- [ ] 列出具体问题

### 综合评价
[正面评价 + 需要改进的方面]
```

## 审查标准

| 级别 | 含义 | 处理方式 |
|------|------|----------|
| CRITICAL | 安全漏洞 / 数据丢失风险 / 架构破坏 | 必须修复 |
| HIGH | 功能 bug / 性能严重问题 | 必须修复 |
| MEDIUM | 代码质量 / 规范偏离 | 建议修复 |
| LOW | 风格优化 / 重构建议 | 可选 |
